> Portable 自身的实机会话/真实模型请求、真实机构检索、第二台电脑验收，以及**升级后的运行期

> 兼容性边界（必须分清，不可混写）：

> * **Portable RC3** 在 `0.2.1-rc.2` 上只完成静态与隔离协议验证，独立实机会话为

## 2. 结果口径与证据规则

* **PASS 必须有执行证据**（JSON/log/artifact）；没有执行的项目只能是 `NOT TESTED`。
* 只读动作（`check` / `plan` / `status` / `verify`）的"只读"用**沙箱树指纹**证明：
  文件集合、内容哈希、大小、mtime 在动作前后一致（允许的例外只有显式 `-OutFile` 与文档声明的
  `%TEMP%` 探针）。
* 升级类用例不得只看退出码：必须校验**目标状态逐字节等于包内载荷**、
  环境元数据字段正确、`.venv`/Profile/用户数据指纹不变、回滚后逐字节回到 RC2。
* 兼容性声明不因"生产 Bundle 的 PASS"升级；不使用旧补丁包的 PASS 迁移到统一包。
* 证据不随发行版分发；发行版只携带可复现命令与判定标准。

## 4. 统一安装/升级包：必须执行的 A–K 矩阵（本轮）

统一发行包发行前必须在统一发行包上执行下列各组，并留下证据。
**本文件不预写任何未执行组的 PASS**；最终发行资格以构建时实际执行结果为准。

| 组 | 范围 | 关键判定 |
|---|---|---|
| A | 全新安装（CHECK/PLAN/INSTALL/VERIFY/STATUS；link+junction；隔离 DSH home；恢复） | check/plan 只读；install exit 0；Profile 解析 bundle；幂等；卸载/安装器回滚可用 |
| B | `RC2_CLEAN → 统一版` | CHECK 只读；PLAN 只读 + planId；APPLY `COMMITTED`；目标树逐字节等于包内 115 载荷 + `manifest.json`；2 个环境文件更新且非迁移字段保留；venv/用户数据/Profile 不变；VERIFY `FILE_UPGRADE_COMPLETE=PASS` |
| C | `RC2_HOTFIXED → 统一版`（2 个 `cordis.patch.yml` 字节变体） | 变体被正确识别；APPLY 后目标状态一致；干净 RC2 不被误判为 hotfix |

**结果记录要求**：每组一行（`PASS` / `WARN` / `FAIL` / `NOT TESTED`）+ 证据文件路径；

**运行期激活**（`DSH_RUNTIME_ACTIVATION_VERIFIED`）在 A–K 中始终为 `NOT TESTED`：
文件级完成与真实 DSH 会话验收是两件事。

## 5. 如何复现

```powershell
# ---- 统一发行包（构建与包级校验）----
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build_unified_release.ps1 `
  -Rc2Zip "<冻结 RC2 ZIP>" -Rc3FrozenZip "<冻结 RC3 ZIP>" -Repo "<候选仓库>" -OutDir "<发布资产目录>"
node tools\build_manifest.mjs --check
node tests\test_static_package.mjs
node tests\test_unified_package.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify_release_zip.ps1 -Zip "<候选 ZIP>"

# ---- 统一矩阵（升级/回滚/故障注入/未知状态/用户数据保护）----
powershell -NoProfile -ExecutionPolicy Bypass -File tests\Test-UnifiedMatrix.ps1 `
  -Rc2Zip "<冻结 RC2 ZIP>" -UnifiedZip "<候选 ZIP>"

# ---- 统一验证（全新安装/安装器回归/包完整性/MCP/归档）----
powershell -NoProfile -ExecutionPolicy Bypass -File tests\Test-UnifiedVerification.ps1 -UnifiedZip "<候选 ZIP>"

# ---- 用户侧只读检查（不安装）----
powershell -NoProfile -ExecutionPolicy Bypass -File tools\setup.ps1 -Action check
powershell -NoProfile -ExecutionPolicy Bypass -File tools\setup.ps1 -Action check -InstallRoot "<RC2 根>"

# ---- 历史/兼容套件（旧安装器语义）----
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_all.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools\portable.ps1 -Action check
```

`tests\run_all.ps1` 的 D 组（隔离 `DSH_HOME` 安装）与 E 组（真实检索）会修改本机环境或需要
机构登录，运行前请先阅读 `docs/02` 与 `docs/04`；无法证明隔离时应保持 `NOT TESTED`。
统一矩阵/验证套件会把所有写操作限制在隔离沙箱中（合成 Layout-A RC2 安装、隔离 DSH home、
重定向 `USERPROFILE`），**不要**把它们指向真实安装根或生产 home。

## 7. 发行等级说明

* `DEVELOPMENT`：代码未完成。
* **`RELEASE CANDIDATE`（本发行版当前等级，统一安装/升级包，Pre-release）**：主要功能与允许的自动测试通过，
  但尚未在独立目标机器上完成完整实测，且统一发行包必须重新执行 A–K 矩阵。
* `VERIFIED RELEASE`：需要在全新或受控的目标 Windows 环境完成真实安装、真实模型请求、
  合法机构认证、真实文献检索以及卸载/回滚验证；对 RC3 还包括在 DSH `0.2.1-rc.2` 上完成
  Portable 自身的独立实机会话验收；对统一发行包还包括一次真实的 RC2→统一版升级 + 运行期验收。

本发行版**不是** Verified Release，请勿如此描述。`DSH_RUNTIME_ACTIVATION_VERIFIED`
在所有报告中保持 `NOT TESTED`。
