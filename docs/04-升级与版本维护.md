# 04 — 升级与版本维护

面向两类人：**使用者**（怎么升级/怎么退回）与**维护者**（怎么改这个发行版）。

---

## 1. 使用者视角

### 1.1 升级到新的发行版

1. 解压新的发行包到一个**新目录**（不要覆盖正在使用的安装根目录）。
2. 先只读检查：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File tools\portable.ps1 -Action check
   ```

   确认 DSH 版本、Python、uv、Chromium 都还是 PASS。
3. 安装：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File tools\portable.ps1 -Action upgrade
   ```

   `upgrade` 与 `install` 走同一流程：先备份、再经官方 `dsh plugin` 安装。
   因为同名包已经存在，安装器会要求 `-Force` 才会覆盖——这正是"不静默覆盖"的设计。
4. 若需要旧的安装根目录：**不要**直接删。先 `-Action uninstall` 再删除，
   或确认没有 Profile 指向它（`-Action status` 会打印链接目标）。
5. 想要退回：`-Action rollback`（用备份）或重新 `install` 旧发行版。

### 1.2 检查当前装的是哪个版本

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\portable.ps1 -Action status
```

会打印 `_portable\install-state.json` 记录的发行版号、bundle 版本、解释器与包版本、
链接目标、备份目录。

### 1.3 只升级 cnki-mcp（不换发行包）

发行包固定 `cnki-mcp 0.1.1`。如果上游发布了修复版而发行包还没更新，可以：

```powershell
# 1) 选一个可写位置作为新的安装根目录
# 2) 用 -Upstream pypi -UpstreamVersion <版本> 重装
powershell ... -Action install -Upstream pypi -UpstreamVersion 0.2.0 -Force
```

或者直接在现有 venv 里升级后用 `-Action diagnose` 复核：

```powershell
<InstallRoot>\.venv\Scripts\python.exe -m pip install -U "cnki-mcp==<版本>"
powershell ... -Action diagnose
```

> 注意：用 `-Upstream pypi` 时 `uv.lock` 的精确固定不再生效，
> `install-state.json` 里的 `packages` 字段会记录实际装上的版本。
> 生产使用建议等发行包更新。

## 2. 维护者视角

### 2.1 目录职责

| 路径 | 谁改 |
|---|---|
| `bundle/cnki-research/**` | 插件本体：Preset 声明、启动器、Skill |
| `upstream/cnki-mcp/**` | 上游源码，**只从上游同步**，不手工改 |
| `tools/**` | 安装器、探针、清单生成器、打包器 |
| `tests/**` | 自动测试 |
| `docs/**` | 说明文档；`docs/provenance/**` 是冻结记录，**不要改** |
| `manifest.json` | **生成物**，不要手改 |

### 2.2 发布流程

```powershell
# 1) 改版本
#    VERSION            -> 例如 1.0.1
#    CHANGELOG.md       -> 记录本次变更
#    manifest.json 由下面第 3 步重新生成

# 2) 跑全部测试
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_all.ps1

# 3) 重新生成 manifest.json（逐文件 SHA-256）
node tools\build_manifest.mjs

# 4) 校验 manifest 与工作区一致
node tools\build_manifest.mjs --check

# 5) 再跑一次静态测试（它会核对 manifest 的哈希）
node tests\test_static_package.mjs

# 6) 打可分发压缩包
powershell -NoProfile -ExecutionPolicy Bypass -File tools\package_release.ps1
```

打包器会：

* 按 `manifest.json` 的 `files` 列表挑选内容 —— 因此 `_scratch\`、`dist\`、
  `.venv\`、`node_modules\`、`_portable\`、`__pycache__\` 天然被排除；
* 再次逐文件核对 SHA-256，不一致就中止；
* 产出 `dist\cnki-research-portable-<版本>.zip` 与其 `.sha256`。

### 2.3 同步上游新版本

```powershell
# 1) 在别处 clone 上游到目标 commit
git clone https://github.com/sepinetam/cnki-mcp <临时目录>
git -C <临时目录> checkout <commit>

# 2) 只替换这三个部分，不要带入 .git / .venv / __pycache__
#    upstream/cnki-mcp/src
#    upstream/cnki-mcp/tests
#    upstream/cnki-mcp/{pyproject.toml,uv.lock,LICENSE,README.md}

# 3) 重算来源哈希
#    重新生成 docs/provenance/upstream-src.sha256.json

# 4) 检查启动器是否还需要
#    <InstallRoot>\.venv\Scripts\python.exe bundle\cnki-research\launcher\cnki_research_launcher.py --selfcheck
#      "VERDICT: upstream stdio transport is still broken" -> 保留启动器
#      "VERDICT: upstream may be fixed"                   -> 可改成直接 `cnki-mcp serve --transport stdio`

# 5) 在 manifest.json 的生成器里更新 dependencies.cnkiMcp.version
#    以及 tools\build_manifest.mjs 里的 pypi 哈希（若用 pypi 策略）

# 6) 跑测试 + 重新生成 manifest + 打包
```

**版本固定原则**：`dependencies.cnkiMcp.version` 与 `upstream/cnki-mcp/uv.lock`
必须同时更新，且 `tests/test_static_package.mjs` 的 `A5.dependencyPins` 会验证
`cnki-mcp`/`mcp`/`playwright` 都还在锁文件里。

### 2.4 修改路径契约时的检查清单

改 `cordis.patch.yml` 的任何 `!!js` 之后，必须确认：

- [ ] `node tests\test_static_package.mjs` 的 `A7.dialect`、`A7.pathResolution`、
      `A7.totalFallback` 全 PASS；
- [ ] 表达式中**没有任何** `throw` 路径（`try/catch` 覆盖全部文件读取）；
- [ ] 表达式返回**字符串**（不是 undefined/null/对象）；
- [ ] `A3.patchNoAbsolutePath` 仍然 PASS（没有盘符）；
- [ ] `dsh --profile <测试 Profile> --dump-config` 仍能组合出该 Preset；
- [ ] 重新生成 `manifest.json`。

### 2.5 修改工具 Schema 时的检查清单

- [ ] `tests\run_all.ps1` 的 Schema 组两态都跑：默认（逐字）与 `--sanitize-schema`；
- [ ] 工具数量仍为 8，名字不变；
- [ ] `mcp__cnki__<name>` 长度 ≤ 64 且字符集为 `[A-Za-z0-9_-]`；
- [ ] 不在顶层引入 `$schema` / `$ref` / `$defs` / `default: null`（provider 会拒绝）；
- [ ] 保留 v1.0 行为：默认路径**不改变**任何已发布 Schema。

### 2.6 版本号约定

* `VERSION` / `manifest.distribution.version`：发行版号，语义化版本。
* `bundle/cnki-research/package.json` 的 `version`：插件版本。**只有插件本体
  （Preset / 启动器 / Skill）变化时才递增**；仅改文档或工具时保持不变。
* 静态测试 `A2.identity` 会强制 `VERSION`、`manifest.distribution.version` 与
  `manifest.bundle.version` 三者自洽。

## 3. 变更影响速查

| 改了 | 必须重跑 | 必须重新生成 | 使用者需要做什么 |
|---|---|---|---|
| 文档 | 无 | 打包 | 重装或只看新文档 |
| 安装器 | `run_all.ps1` | `manifest.json` | 重装 |
| Skill | `run_all.ps1` + 手工看技能是否出现 | `manifest.json` | 重装 |
| 启动器 | `run_all.ps1`（MCP + Schema 组） | `manifest.json` | 重装 |
| `cordis.patch.yml` | 上述全部 + `--dump-config` | `manifest.json` | 卸载后重装 |
| 上游源码 | 依赖可复现性测试 + `--selfcheck` | 来源哈希 + `manifest.json` | 重装 |
| 依赖版本 | 依赖可复现性测试 | `manifest.json` | 重装 |
