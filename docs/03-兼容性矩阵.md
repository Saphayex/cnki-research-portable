## 2. DSH Desktop

DSH 兼容性按"谁被验证"分三个对象，**禁止把生产 Bundle 的实机结果算作 Portable 的 PASS**。

| 对象 | DSH 版本 | 状态 | 依据 |
|---|---|---|---|
| Portable 发行版（历史实机） | `0.2.0-rc.2`（Electron 44.0.0） | **已验证** | 历史安装、隔离 Profile、MCP 握手等实机测试记录 |
| Portable RC3（静态 + 隔离协议） | `0.2.1-rc.2`（Electron 44.0.0） | **已验证（仅静态/隔离）** | Preset 不再引用已移除的 `{{cwd}}`；YAML/组合解析、MCP 协议、隔离 `DSH_HOME` 安装 |
| Portable RC3（独立实机会话） | `0.2.1-rc.2` | **NOT TESTED** | 未做独立安装后的真实会话/模型请求 |
| 本机生产 Bundle（**独立对象**） | `0.2.1-rc.2` | **真实验收 PASS** | 生产验收：模型请求、Prompt Assembly、8 工具、资源、登录取用、真实检索 |

| 项目 | 值 |
|---|---|
| 声明区间 | `>=0.2.0-rc.2 <0.3.0` |
| Portable verified list | `0.2.0-rc.2`（仅此一个） |
| 同 0.2.x 的其他补丁版本 | 未验证（`check` 会报 `UNTESTED`，不阻止安装） |
| 0.3.x 及以上 | 未验证；`check` 会报 `UNTESTED`，安装前请先看发行说明 |

### 2.1 本版修复的兼容性问题（CNKI-021-001）

DSH `0.2.1-rc.2` 移除了隐式的 `cwd` 提示词变量：`@deepseek-ai/dsh-agent-loop` 只注册
`provider` 与 `model`（`0.2.0-rc.2` 还注册 `cwd`）。旧 Preset 的 persona suffix
`Your working directory is {{cwd}}.` 会在首次模型请求前的 Prompt Assembly 阶段被严格
插值拒绝（未知变量直接抛错），整个会话无法开始。

RC3 的修复是**删除该行**，保留
`prefix: You are a coding agent powered by the {{model}} model.`。
静态回归断言 `A7.promptVariables` 会检查 persona 文本只引用 `provider` / `model`；
`{{cwd}}` 一旦回归立即 FAIL。

**结论边界：** 修复逻辑已由本机生产 Bundle 的 `0.2.1-rc.2` 真实验收证明；但 Portable RC3
自身的独立安装与实机会话验收仍为 `NOT TESTED`，不因生产 Bundle 的 PASS 而升级。

### 2.2 升级路径的 DSH 兼容性（与全新安装分开陈述）

统一发行包的 RC2→RC3 安全升级**只改文件、不改变环境依赖**，因此：

| 项目 | 结论 | 依据 |
|---|---|---|
| 升级会引入新的 DSH 版本要求吗 | **否** | 升级不重建 venv、不重跑插件管理器、不改 Profile；`bundle/cnki-research/**` 与 `upstream/cnki-mcp/**` 与冻结 RC3 逐字节一致 |
| DSH 需要处于什么状态 | **必须正常退出后 APPLY** | 真实生产 home + DSH 进程运行 → `DSH_IN_USE` 拒绝；隔离目标 → WARN 放行 |
| DSH 模式要求 | 只需普通 PowerShell（DSH Standard 会话的命令工具也可）；**不需要 Creator** | 文件级升级不调用 Plugin Manager；Creator 只在全新安装/卸载/安装器回滚等 Plugin Manager 场景需要 |
| 升级后如何生效 | 正常重新打开 DSH（不要强杀、不要改 Profile 触发 HMR） | Profile junction 与 `link:` 引用不变 |
| 运行期激活是否已验证 | **`NOT TESTED`** | 文件级完成 ≠ 真实会话/模型请求/工具可见性；需用户在本机验收 |
| 升级路径的执行验证 | 隔离沙箱按 A–K 组矩阵执行 | 结果以构建时实际执行证据为准；未执行项 = `NOT TESTED`（见 `docs/05`） |

升级只支持**标准原地安装（Layout A）**；`-InstallRoot` 指向别处的独立运行根（Layout B）
不在增量升级范围内（检测为 `LAYOUT_SEPARATE_PACKAGE_ROOT` 并拒绝，人工迁移见 `docs/04`）。

### 2.3 旧版 DSH 0.2.0-rc.2 的回归

结论：**静态兼容成立，实机回归 `LIVE NOT TESTED`。**

* `dsh-persona` 的 `suffix` 是可选字段，默认 `""`（`0.2.0-rc.2` 与 `0.2.1-rc.2` 相同）；
  删除该行后配置仍然合法，且空 suffix 不产生任何插值，不会进入 0.2.0 的错误路径。
* persona `prefix` 使用 `{{model}}`；`0.2.0-rc.2` 的 agent-loop 注册了
  `provider` / `model` / `cwd`，因此 prefix 在旧版上照常可用。
* 没有为了验证旧版而回退当前生产 Desktop；`0.2.0-rc.2` 的实机结论只能由独立的旧版环境给出。

### 用到的 DSH 接口

| 包 | 用法 |
|---|---|
| `@deepseek-ai/dsh-agent-preset` | 声明 Preset（`id`/`name`/`description`/`order`/`plugins`） |
| `@deepseek-ai/dsh-mcp-client` | `serverName`、`transport: stdio`、`command`/`args`/`cwd`、`toolCallTimeoutMs`、`failOnStartupError`、`maxInstructionBytes`、`reconnect.*` |
| `@deepseek-ai/dsh-skill-filesystem` | `customSkillDirs` |
| `@deepseek-ai/dsh-tool-skill` | 技能工具 |
| `@deepseek-ai/dsh-plugin-manager` | `dsh plugin --profile <p> add/remove`（转发 pnpm） |
| Cordis loader `!!js` | entry config 的运行期求值（`interpolate`） |

任何一个接口变更都可能影响本发行版；升级 DSH Desktop 后请重跑
`tests\run_all.ps1`。

## 5. 网络与外部依赖

| 阶段 | 需要网络 | 目标 |
|---|---|---|
| `setup.ps1 -Action check` | 否 | — |
| `setup.ps1 -Action plan`（全新安装计划） | 否 | 只读，不下载任何东西 |
| 安装 Python 依赖（`-Action install`） | 是（除非 uv 缓存已预热，可用 `-Offline`） | PyPI（`uv` 默认源） |
| 下载 Chromium（`-Action install`） | 是（若本机已存在 `chromium-1243` 则复用） | `playwright.azureedge.net` 等 Playwright CDN |
| `-Action install` 之后 | 否（相对于安装） | — |
| **RC2→统一版升级**（`check` / `plan` / `upgrade` / `verify` / `rollback`） | **否（全程离线）** | 升级引擎只读包内已校验的目标字节，不调用 Node/Git/Python/uv，不联网 |
| 检索时 | 是 | `cnki.net` / `fsso.cnki.net` |
| 模型调用 | 是 | DSH 自身配置的模型服务 |

**不需要** `http://127.0.0.1:7788`（上游的 HTTP 传输）。本发行版只用 stdio，
`tools/probe_mcp_stdio.py` 会验证这一点。

## 6. 路径字符兼容性

| 路径形态 | 状态 | 验证方式 |
|---|---|---|
| 安装根含空格（如 `D:\My Tools\CNKI Research`） | **已验证** | 静态测试 A7 用 `安装 目录`（空格 + 中文）做模拟布局求值 |
| 安装根含中文（如 `D:\我的工具\知网`） | **已验证** | 同上 |
| PackageRoot（解压目录）含空格/中文、且与 InstallRoot 分离 | 由统一矩阵与归档校验覆盖（含空格 + 中文路径用例） | 以实际执行证据为准 |
| 发行 ZIP 文件名 `CNKI-Research-Portable-1.0.0-rc.3.zip` 含连字符 | **支持**；命令示例始终使用引号 | — |
| 深层嵌套（> 200 字符） | 未验证 | Windows 长路径行为未实测 |
| UNC 路径（`\\server\share`） | 未验证 | 未实测 |
| 只读位置（如 `C:\Program Files`） | 不支持 | 安装器需要写入 `.venv`；请用 `-InstallRoot` 指向可写目录 |
| PackageRoot 与 InstallRoot 相同且已有安装标记 | **不支持（拒绝）** | 防止“新 ZIP 解压覆盖旧安装目录”的混合状态；`setup.ps1 -Action check` fail-closed |

本机实际验证时使用的安装根目录同时包含**空格**与中文，以覆盖最不利的路径形态；
对应的自动化断言是 `tests/test_static_package.mjs` 的 A7 组（求值 `!!js` 表达式）。

| 场景 | 状态 |

| Profile 中已有其他 `@local/*` 或第三方 bundle | 未专门验证；安装器只增删自己的包名与 `dsh.profile.bundles` 条目 |

| 与 v1.1 `cnki-runtime` 共存 | **未验证，且不需要**；本发行版不依赖也不引入 v1.1 |

## 8. 已知不支持的场景

* 无 DSH Desktop 的纯 CLI 环境（本插件是 Preset，必须有宿主）。
* 无 Python 且无法安装 uv 的离线机器上的**全新安装**（可在有网机器上预热 uv 缓存后带 `-Offline`）。
* 需要**全文下载**的用途（上游不提供）。
* 需要无人值守的机构认证（必须人工在浏览器窗口完成）。
* **Layout B（独立运行根）的增量升级**：请按 `docs/04` 的人工迁移方案处理。
* **把新 ZIP 解压覆盖到旧安装目录**：混合状态会被拒绝，不提供自动修复。
* **DSH 运行中执行升级 APPLY/ROLLBACK**：会被拒绝（`DSH_IN_USE`；隔离目标仅 WARN）。
* **Windows 10 / ARM64 / Linux / macOS**：未验证，不声称可用。
